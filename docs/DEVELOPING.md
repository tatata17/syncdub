# 開発メモ

## ファイルの役割
- `syncdub.pyw` … 正式版。利用者はこれを使い、`version.json` を見て自動更新する。
- `beta/syncdub_beta.pyw` … ベータ版(試験中)。ふだんの作業はこちらで行う。`beta/version.json` を見て自動更新する。正式版の利用者には届かない。
- `tools/release.py` … 公開前の確認と、`version.json` / `beta/version.json` の書き出し。

## ベータ版の公開手順
1. `beta/syncdub_beta.pyw` を直し、`BETA_BUILD` を1つ上げる(`BETA_REVIEW = True` のまま)
2. `python tools/release.py beta "更新内容のひとこと"` … 確認して `beta/version.json` を書く(SHA-256 も入る)
3. `beta/` だけを commit して `main` に push する

## 正式版の公開手順(ベータ版を正式版にする)
ベータ版をそのままコピーすると、正式版がベータの更新先を見にいってしまう。必ず次の順で行う。

1. `beta/syncdub_beta.pyw` を `syncdub.pyw` にコピーする(部分的に移さない。ベータを正として丸ごと置き換える)
2. `syncdub.pyw` の `BETA_REVIEW = False` にする
   - 確認: `grep -n "^BETA_REVIEW" syncdub.pyw` が `False` になっていること
3. `syncdub.pyw` の `APP_VERSION` を上げる(`beta/` 側は触らない)
4. `python tools/release.py official "更新内容のひとこと"` … `BETA_REVIEW` が `False` でなければ止まる。通れば `version.json` を書く
5. `docs/changelog.json` の先頭に履歴を1件追記する
6. 起動して確かめる
   - タイトルと右上のバージョン表示に「ベータ」が出ていない
   - 「録画から探す」のあとに確認ウインドウが勝手に開かない
   - 「更新を確認」で「最新版です」と出る(ベータの番号が出ない)
   - 合成のあとの自動チェック、「成功として記録」、「記録と比べる」は、正式版でも動く(これは正しい)
7. `python tools/promote_check.py` が OK になる(正式版とベータ版の違いが `BETA_REVIEW` / `APP_VERSION` / `BETA_BUILD` の行だけ、
   両方の `version.json` の sha256 と版番号が本体と合う、両方 py_compile が通る、を確かめる。違いの確認は目で見ず、これに任せる)
8. commit して `main` に push する
9. そのあとベータ版も同じ `APP_VERSION` に上げ、`BETA_BUILD` を上げて公開する(ベータ版の利用者が古い版に取り残されないように)

`BETA_REVIEW = True` のときだけ変わる所: 更新先(`beta/version.json`)、バックアップ先(`syncdub_beta_backups`)、
タイトルとバージョン表示の「ベータ」、「録画から探す」の確認ウインドウの自動表示。
(合成後の自動チェックと報告文、成功の記録、記録と比べるは、v2026.11.16.42 から正式版にも入っている)

## ベータ版にだけ入っている変更(次の正式版で、更新履歴と使い方ページに書く)
正式版にしたら、この一覧を消す。

- 保存先が英語版・日本語の録画そのものになっているときは、合成しない(ベータ24)
- 手動調整: 波形の上で、緑の線や範囲の端をドラッグして動かせる。ふつうのドラッグはつかんだ側だけ、
  Shift+ドラッグは上下一緒に動かす。ダブルクリックで数字の編集(ベータ25〜27)
- 手動調整: 線をドラッグして離すと、動かした側を音で微調整する(±0.3秒、相関0.35以上のときだけ。
  「登録するとき・線をドラッグしたとき、音で微調整する」のチェックで切れる)。一覧で点を選んで←→(または Alt+←→)で
  1コマずつ動かす(Shift: 0.1秒、Ctrl: 10コマ。2秒以内の連続は Ctrl+Z 1回分)。ドラッグ中に時間差の変化を表示、
  つかめる線の強調、ドラッグ中の Esc で取り消し、右クリックに「ここに『同じ場面』を追加」(ベータ28)
- 想定外のエラーを `syncdub_error.log` に記録し、次の起動で1回知らせる。「更新・設定」→「診断情報を保存」。
  設定を保存できなかったときは、起動中に1回だけ知らせる(ベータ29)
- 手動調整: 波形の下に横スクロールバー。右クリックでメニュー(CMではない、カットではない、点を消す、など)(ベータ27)

## 自動テスト(人工の素材)
`python tools/selftest.py` … 人工の音で作った英語版・日本語版の組(一定のずれ、日本語側だけのCM、英語側だけの場面、
ゆるやかなドリフト、12秒未満の短いCM)を自動合わせにかけ、仕込んだ答えと比べる。10秒あまりで終わる。NG があれば終了コード 1。
本体を直したら回す。人工の音は本物の吹き替えと性質が違うので、下の実物での確認と「記録と比べる」の代わりにはならない(併用する)。

## 正式版にする前の確認(回帰確認の最小セット)
実物の素材での確認は自動化していない。正式版にする前に、次の種類の素材で一度ずつ動かして確かめる。素材の実名は、ここや公開ページには書かない。

かんたん(1本に合わせる)
- ふつうの回 … CMをはさむ30分枠。区間の数と「使いません」の範囲が前の版と変わらない
- 冒頭の曲に、英語版だけナレーションが入る回 … 冒頭が1区間でつながり、途中が無音にならない
- CMの前後に、日本語の録画にだけジングルが入る回 … 英語が無音の所に日本語の音が入らない
- 英語版が無音・暗転で終わる回 … 最後に、日本語の録画の次の番組の音が入らない
- 音だけでは合わない回(「映像でも合わせる」を入れる) … 暗転の所に偽の区間ができない
- ベータ版では、合成後の自動チェックが「問題は見つかりませんでした」になること

録画から探す
- ふつうのCM(15秒・30秒・60秒)
- 短縮版(60秒 → 30秒など)
- 音が英語版と違う版(ナレーションや曲が違う)
- 12秒未満の短いCM
- 1時間を超える録画で、後半ほど音と映像がずれるもの … 音ズレの自動補正がかかり、補正後の測定がほぼ0になる
- 中止 … すぐ止まり、書きかけのファイルが残らない

## 成功の記録と回帰チェック
テストの自動化の代わりに、利用者のPCにある実物の素材で確かめるしくみ。素材と記録はリポジトリに入れない(番組名が入るため)。

- 記録: 「かんたん」タブで合成 → 自動チェック → 見て・聞いて問題なければ「成功として記録」。
  本体と同じフォルダの `syncdub_記録/` に、素材の場所・合わせ方・区間の一覧・版・自動チェックの結果・メモが json で残る。
- 比べる: 「更新・設定」→「記録と比べる (回帰チェック)」。記録の素材を今の版で合わせ直し(合成はしない)、
  区間の一覧と、合成せずに測った数字(ずれ・途切れなど)を記録と比べる。コマンドからは `python tools/regress.py`。
- 判定: 変化なし / 変化あり(測定は良くなった・同じ・悪くなった) / 素材が見つからない。
  区間が変わっただけでは不具合とは限らない(改良でも変わる)。「測定が悪くなった」を優先して調べる。
- 大きめの直しのあとと、正式版にする前に回してもらい、結果の文面を受け取って確認する。
- 使い方は `docs/beta.html`(ベータ版の使い方ページ)に書いてある。ベータ版の機能を変えたら、このページも直す。

## コードの置き方
1つのファイルで配る前提なので、ファイルは分けない。新しく書く計算の処理は、App のメソッドではなく、できるだけモジュールの関数に置く
(画面なしで tools/ から呼べて、テストしやすいため)。

## 使い方ページ
`docs/index.html` を GitHub Pages で公開している(Settings → Pages → Branch `main` / `/docs`)。
最新版の表示は `version.json`、更新履歴は `docs/changelog.json` から読み込む。
ベータ版の使い方は `docs/beta.html`(正式版のページからはリンクしない。デザインは `index.html` の `<style>` をそのまま使う)。
